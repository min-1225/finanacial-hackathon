# SecondSign 기능명세서

**팀명**
계란말이

**구성원 성명**
최지원, 이상민

---

## 1. MVP 구현 범위*

SecondSign MVP는 비대면 채널에서 투자상품 가입을 고려하는 사용자가 자신이 사전에 확정한 금융 원칙과 상품 문서의 핵심 조건을 가입 직전에 직접 대조할 수 있도록 지원하는 웹 기반 AI 검증 서비스다.

SecondSign은 사용자의 상황과 상품설명서를 생성형 AI에 한 번에 입력해 상품의 적합성이나 안전성을 판단하도록 하지 않는다.

사용자의 자연어 입력, 상품 문서, 상품 조건, 원문 근거, 판정 규칙을 단계별로 구조화하고, 각 단계의 결과를 검증한 뒤 다음 단계로 전달하는 방식으로 전체 검증 흐름을 구성한다.

MVP에서는 다음 다섯 가지 금융 원칙만 검증한다.

* 원금손실 허용 여부
* 허용 가능한 손실 한도
* 자금 사용 예정 시점과 상품 만기
* 중도환매 가능 여부 및 중도환매 시 손실
* 예금자보호 필요 여부

사용자는 자신의 자금 목적과 조건을 자연어로 입력한다. 생성형 AI는 이를 자금 목적, 사용 예정 시점, 원금손실 허용 여부, 허용 손실 한도, 중도인출 필요 여부, 예금자보호 필요 여부의 구조화된 항목으로 변환한다.

입력 내용 중 의미가 불명확하거나 검증에 필요한 값이 확정되지 않은 경우에는 필요한 항목에 대해서만 추가 질문한다.

사용자는 구조화된 금융 원칙을 직접 확인하고 수정한 뒤 최종 확정한다. 사용자가 확정하기 전의 AI 해석값은 상품 검증에 사용하지 않는다.

상품 분석에는 MVP에서 제공하는 가상 원금 비보장형 구조화 투자상품 설명서를 사용한다.

문서 분석 단계에서는 상품명, 문서 종류, 작성일, 페이지 구성 및 누락 여부를 확인한다. 정상적으로 확인된 문서에 대해서만 원금손실 가능 여부, 손실 제한 조건, 만기, 중도환매 조건, 예금자보호 여부를 추출한다.

추출한 각 상품 조건에는 해당 내용을 확인할 수 있는 원문과 페이지를 함께 연결한다.

사용자가 확정한 금융 원칙과 근거가 확인된 상품 조건은 별도의 규칙 기반 검증 로직에서 비교한다.

검증 결과는 다음 세 가지 상태로 구분한다.

* **원칙 위반:** 상품 문서에 명시된 조건이 사용자가 확정한 금융 원칙과 직접 충돌하는 경우
* **검증 보류:** 필요한 정보가 문서에 없거나 근거가 충분하지 않아 판단할 수 없는 경우
* **관련 조건 확인:** 해당 금융 원칙과 관련된 상품 조건과 근거를 확인한 경우

최종 화면에서는 사용자가 확정한 금융 원칙, 발견된 원칙 위반, 검증 보류 항목, 상품 문서의 근거 문장 및 페이지를 가입 전 검증 결과로 제공한다.

MVP에서는 특정 금융상품 추천, 상품 전체의 적합성·안전성 판정, 미래 수익률 및 손실률 예측, 실제 금융상품 가입, 금융계좌 연동 기능은 구현하지 않는다.

각 단계의 결과가 사전에 정한 조건을 만족한 경우에만 다음 단계로 전달한다.

## 3. 사용자 이용 흐름*

### 1단계. 금융 원칙 입력

사용자는 자신의 자금 목적과 조건을 자연어로 입력한다.

예시:

“1년 뒤 전세자금으로 사용할 돈이고 원금 손실은 원하지 않습니다. 필요하면 중간에 돈을 찾을 수 있어야 합니다.”

### 2단계. 금융 원칙 구조화 및 추가 확인

입력한 문장을 다음과 같은 검증 가능한 항목으로 변환한다.

* 자금 목적: 전세자금
* 사용 예정 시점: 1년 후
* 원금손실 허용 여부: 불허
* 허용 손실 한도: 0%
* 중도인출 필요 여부: 필요
* 예금자보호 필요 여부: 미확정

입력만으로 확인할 수 없는 항목은 임의로 값을 생성하지 않고 추가 질문한다.

예를 들어 예금자보호 여부가 입력되지 않았다면 해당 조건이 반드시 필요한지 사용자에게 확인한다.

### 3단계. 금융 원칙 사용자 확정

사용자는 AI가 정리한 금융 원칙을 카드 형태로 확인한다.

잘못 해석된 항목은 직접 수정할 수 있으며, 사용자가 최종 확정한 값만 상품 검증에 사용한다.

### 4단계. 샘플 상품 선택

사용자는 MVP에서 제공하는 가상 원금 비보장형 구조화 투자상품 설명서를 선택한다.

문서 분석을 시작하기 전에 문서 종류, 페이지 구성 및 누락 여부를 확인한다.

### 5단계. 상품 핵심 조건 및 근거 확인

문서에서 다음과 같은 상품 조건을 추출한다.

* 원금손실 가능 여부
* 손실 제한 조건
* 상품 만기
* 중도환매 가능 여부
* 중도환매 시 손실 가능 여부
* 예금자보호 여부

각 조건에는 해당 내용을 확인할 수 있는 원문과 페이지를 연결한다.

근거를 확인할 수 없는 값은 이후 원칙 검증에 사용하지 않는다.

### 6단계. 금융 원칙 대조

사용자가 확정한 금융 원칙과 상품 문서에서 확인된 조건을 규칙 기반 로직으로 대조한다.

예를 들어 사용자가 원금손실을 허용하지 않았는데 상품 문서에서 원금의 일부 또는 전부를 잃을 수 있다고 명시되어 있다면 `원칙 위반`으로 처리한다.

필요한 상품 조건을 문서에서 확인할 수 없는 경우에는 임의로 적합하다고 판단하지 않고 `검증 보류`로 처리한다.

### 7단계. 가입 전 검증 결과 확인

사용자는 최종 화면에서 다음 내용을 확인한다.

* 내가 확정한 금융 원칙
* 발견된 원칙 위반
* 검증 보류 항목
* 상품 문서에서 확인된 조건
* 판단에 사용한 원문
* 해당 원문의 페이지

SecondSign은 상품의 안전성, 적합성 또는 최종 가입 여부에 대한 종합 판정을 제공하지 않는다.

## 4. AI 및 데이터 처리 방식*

### 4-1. AI 적용 방식

SecondSign은 생성형 AI에게 사용자 상황과 상품 문서를 모두 전달한 뒤 “이 상품이 적합한지 판단해 달라”고 요청하는 방식으로 구현하지 않는다.

대신 생성형 AI가 잘할 수 있는 자연어 및 문서 이해 영역과, 반드시 일관된 기준이 필요한 금융 원칙 판정 영역을 분리한다.

전체 데이터 흐름은 다음과 같다.

**사용자 자연어 입력**
→ 금융 원칙 구조화
→ 불명확 항목 확인
→ 사용자 직접 확정

**상품 문서**
→ 문서 상태 확인
→ 상품 핵심 조건 추출
→ 원문 및 페이지 연결
→ 추출 결과 검증

**확정 금융 원칙 + 근거가 확인된 상품 조건**
→ 규칙 기반 검증
→ 원칙 위반 / 검증 보류 / 관련 조건 확인
→ 사용자에게 근거와 함께 결과 제공

SecondSign은 이처럼 생성형 AI의 추론 결과를 그대로 최종 금융 판단으로 사용하지 않고, AI의 입력과 출력 범위를 단계별로 구조화하고 검증하면서 서비스를 실행한다.

---

### 4-2. 생성형 AI의 역할

생성형 AI는 다음 작업에 활용한다.

첫째, 사용자의 자연어를 검증 가능한 금융 원칙 항목으로 구조화한다.

둘째, 사용자의 입력 중 의미가 불명확하거나 추가 확인이 필요한 항목을 식별하고 확인 질문을 생성한다.

셋째, 상품 문서의 문장, 표, 각주 등에서 사전에 정의한 상품 조건과 해당 원문 후보를 추출한다.

생성형 AI는 다음 작업을 수행하지 않는다.

* 금융상품 추천
* 상품 전체의 적합성 판단
* 상품의 안전 여부 판정
* 사용자의 최종 가입 여부 결정
* 미래 수익률 또는 손실률 예측
* 문서에 없는 조건의 임의 생성

---

### 4-3. 구조화 및 검증 방식

SecondSign은 AI가 생성한 자유 형식 문장을 다음 단계의 금융 판정에서 직접 사용하지 않는다.

사용자 입력은 다음 항목으로 구조화한다.

* 자금 목적
* 사용 예정 시점
* 원금손실 허용 여부
* 허용 손실 한도
* 중도인출 필요 여부
* 예금자보호 필요 여부

상품 문서에서는 다음 항목을 구조화한다.

* 원금손실 가능 여부
* 손실 제한 조건
* 상품 만기
* 중도환매 가능 여부
* 중도환매 시 손실 가능 여부
* 예금자보호 여부

상품 조건에는 다음 근거 정보를 함께 저장한다.

* 근거 원문
* 근거 페이지
* 근거 확인 여부

이를 통해 상품 조건이 추출되더라도 원문과 페이지가 확인되지 않는 경우에는 해당 값을 최종 판정에 사용하지 않는다.

SecondSign의 기본 처리 원칙은 다음과 같다.

**사용자 의미가 불명확한 경우 → 추가 확인**

**상품 조건의 근거가 없는 경우 → 판정에서 제외**

**문서에 필요한 정보가 없는 경우 → 검증 보류**

**근거가 확인된 조건 → 규칙 기반 검증에 사용**

---

### 4-4. 규칙 기반 판정

최종적인 금융 원칙 위반 여부는 생성형 AI의 자유로운 판단이 아니라 사전에 정의한 규칙 기반 로직으로 처리한다.

예시는 다음과 같다.

**원금손실**

사용자 원칙: 원금손실 불허
상품 조건: 원금의 일부 또는 전부 손실 가능
→ **원칙 위반**

**허용 손실 한도**

사용자 원칙: 최대 10% 손실 허용
상품 조건: 10%를 초과하는 손실 가능
→ **원칙 위반**

사용자 원칙: 최대 10% 손실 허용
상품 문서: 최대 손실 범위를 확인할 수 없음
→ **검증 보류**

**사용 예정 시점**

사용자 원칙: 1년 후 자금 사용
상품 조건: 만기 3년
→ **원칙 위반**

**중도인출**

사용자 원칙: 필요 시 중도인출이 가능해야 하며 중도인출 시에도 원금 손실 불허
상품 조건: 중도환매는 가능하지만 원금손실 발생 가능
→ **원칙 위반**

**예금자보호**

사용자 원칙: 예금자보호 필요
상품 조건: 예금자보호 대상 아님
→ **원칙 위반**

---

### 4-5. 활용 데이터 및 개인정보 처리

MVP에서 사용하는 소비자 데이터는 다음과 같다.

* 자금 목적
* 사용 예정 시점
* 원금손실 허용 여부
* 허용 손실 한도
* 중도인출 필요 여부
* 예금자보호 필요 여부

MVP에서는 주민등록번호, 계좌번호, 연락처, 실제 투자계좌, 금융회사 거래내역 등의 개인정보 및 실제 금융정보를 수집하지 않는다.

상품 데이터는 공개 금융상품 문서의 형식을 참고하여 제작한 가상 원금 비보장형 구조화 투자상품 설명서를 사용한다.

## 5. MVP 검증 방법*

심사자는 별도 회원가입 없이 제출된 SecondSign 배포 URL에서 핵심 기능을 확인할 수 있다.

MVP에서는 여러 기능을 개별적으로 테스트하기보다 실제 사용자 상황을 기반으로 한 세 가지 핵심 시나리오와 한 가지 예외 시나리오를 제공한다.

---

### 테스트 시나리오 1. 절대 잃으면 안 되는 전세자금

**사용자 상황**

1년 뒤 전세 계약에 사용할 자금이며 원금손실을 허용하지 않고, 필요할 경우 중도인출이 가능해야 하는 사용자다.

**샘플 입력**

“1년 뒤 전세자금으로 사용할 돈이고 원금 손실은 원하지 않습니다. 필요하면 중간에 돈을 찾을 수 있어야 합니다.”

사용자는 추가 확인 과정에서 예금자보호도 필요한 조건으로 확정한다.

**사용자 확정 금융 원칙**

* 사용 예정 시점: 1년 후
* 원금손실: 불허
* 중도인출: 필요
* 중도인출 시 원금손실: 불허
* 예금자보호: 필요

**샘플 상품 조건**

* 만기 3년
* 원금의 전부 또는 일부 손실 가능
* 중도환매 가능
* 중도환매 시 원금손실 가능
* 예금자보호 대상 아님

**예상 결과**

* 원금손실 원칙 → **원칙 위반**
* 자금 사용 시점 → **원칙 위반**
* 중도인출 조건 → **원칙 위반**
* 예금자보호 조건 → **원칙 위반**

각 결과를 선택하면 해당 판정에 사용한 상품 설명서의 원문과 페이지를 확인할 수 있다.

해당 시나리오를 SecondSign MVP의 기본 데모 시나리오로 사용한다.

---

### 테스트 시나리오 2. 최대 손실 한도가 있는 사용자

**사용자 상황**

원금손실 자체는 허용하지만 해당 자금에서는 최대 10%까지만 손실을 감당하려는 사용자다.

**샘플 입력**

“당장 사용할 돈은 아니고 투자할 수 있습니다. 다만 손실은 최대 10%까지만 감당하고 싶습니다.”

**사용자 확정 금융 원칙**

* 원금손실: 허용
* 허용 손실 한도: 최대 10%

**샘플 상품 조건**

상품 설명서에 10%를 초과하는 원금손실이 발생할 수 있다고 명시한다.

**예상 결과**

허용 손실 한도 → **원칙 위반**

결과 화면에서 사용자의 최대 10% 손실 원칙과 상품 문서의 10% 초과 손실 가능 조건을 함께 보여주고 원문과 페이지를 제공한다.

이 시나리오를 통해 SecondSign이 모든 원금 비보장 상품을 동일하게 판단하지 않고 사용자가 직접 확정한 조건을 기준으로 대조하는 것을 확인할 수 있다.

---

### 테스트 시나리오 3. 상품 문서만으로 판단할 수 없는 경우

**사용자 상황**

테스트 시나리오 2와 동일하게 최대 10%까지만 손실을 허용한다.

**사용자 확정 금융 원칙**

* 원금손실: 허용
* 허용 손실 한도: 최대 10%

**샘플 상품 조건**

상품 문서에는 원금손실 가능성만 기재되어 있고 최대 손실 한도를 제한하는 조건은 기재되어 있지 않다.

**예상 결과**

허용 손실 한도 → **검증 보류**

SecondSign은 미래 시장 상황이나 일반적인 상품 위험도를 이용하여 10% 이내의 손실이라고 추정하지 않는다.

대신 상품 문서만으로 사용자의 최대 손실 조건 충족 여부를 확인할 수 없다는 사실과 추가로 확인해야 할 내용을 표시한다.

이 시나리오를 통해 확인할 수 없는 정보를 생성형 AI가 임의로 보완하지 않는 것을 검증할 수 있다.

---

### 예외 시나리오. 불완전한 상품 문서

MVP에서 제공하는 페이지 누락 테스트 문서를 선택한다.

**예상 결과**

시스템이 문서 누락을 감지하고 문서 불완전 경고를 표시한다.

필요한 상품 조건을 확인할 수 없는 상태에서는 정상적인 상품 검증 결과를 생성하지 않는다.

### MVP 제한사항

MVP는 원금 비보장형 구조화 투자상품 샘플을 대상으로 구현한다.

검증 금융 원칙은 다음 다섯 가지로 제한한다.

* 원금손실 허용 여부
* 허용 손실 한도
* 자금 사용 시점
* 중도환매 조건
* 예금자보호 여부

실제 금융회사의 최신 상품 문서를 자동으로 수집하는 기능은 포함하지 않는다.

MVP에서는 서비스가 제공하는 샘플 상품 문서를 중심으로 검증한다.

실제 금융계좌 및 금융회사 시스템과 연동하지 않는다.

미래 가격, 미래 수익률 및 미래 손실률을 예측하지 않는다.

상품 문서에서 필요한 조건을 확인할 수 없는 경우에는 해당 조건을 충족한다고 추정하지 않고 검증 보류로 처리한다.

SecondSign의 결과는 금융상품 추천, 적합성·적정성 평가 및 실제 금융상품 가입 결정을 대신하지 않는다.
